# ADR-001 – Architecture en services séparés (Caddy + Symfony API + Next.js + PostgreSQL)

- Statut : Acceptée
- Date : 24/11/2025

## Contexte

L'application doit proposer :

- une interface d'administration pour gérer des questionnaires,
- une interface répondant pour naviguer dans les parcours,
- une API REST pour la gestion et l'envoi de données.

Le test impose l'utilisation de Symfony côté backend et Next.js côté frontend,
orchestrés par Docker.

## Décision

Nous avons choisi une architecture composée de plusieurs services :

- Caddy comme reverse proxy,
- un backend Symfony exposant une API REST,
- un frontend Next.js pour l'interface utilisateur,
- PostgreSQL comme base de données.

Chaque service est indépendant et configurable via
des variables d'environnement (`.env` / `.env.example`).

## Alternatives envisagées

- Express comme API avec Prisma ORM : rejeté car le backend imposé est Symfony
- Next.js seul avec API Routes (sans Symfony) : rejeté car le backend imposé est Symfony.

## Conséquences

- Séparation claire des responsabilités (API / UI / BDD / proxy).
- Facilité pour changement de structure via Dockerisation.
- Environnement reproductible via Docker.

**Négatives / limites**

- Symfony est très rigide, et PHP verbeux moins pratique.
- Découverte de Symfony.
